# Кулинарная книга в Telegram

Личное приложение: присылаешь боту ссылку на видео (Instagram, TikTok, YouTube) или текст
рецепта — получаешь аккуратный рецепт в мини-аппе со своей библиотекой, поиском, избранным,
планом на неделю и списком покупок. Без подписок, рекламы и платных сервисов.

**Мини-апп:** https://chilipeppers13.github.io/recipe-bot
**Бот:** https://t.me/gabago0l_bot

## Как устроено

```
ссылка → yt-dlp (только звук) → ffmpeg 16 кГц → faster-whisper (локально)
       → LLM → структура рецепта → SQLite (data/recipes.db)
       → снимок сайта (docs/) → GitHub Pages

мини-апп: читает снимок (работает даже с выключенным маком),
          правки/план/покупки отправляет на мак через туннель с подписью Telegram
```

Почему так: GitHub Pages отдаёт только статику, поэтому чтение — из снимка, а изменения —
через API на маке. Никаких серверов в интернете и платы за хостинг.

| файл | что делает |
|---|---|
| `app/bot.py` | бот: ссылки, команды, правка/удаление, белый список |
| `app/pipeline.py` | видео/страница/текст → структурированный рецепт |
| `app/db.py` | SQLite: рецепты, план, покупки, настройки |
| `app/api_server.py` | API для мини-аппа + публикация сайта |
| `app/webapp/app.html` | мини-апп (один файл, без сборки) |
| `scripts/publish.py` | сборка docs/ и пуш на GitHub Pages |
| `scripts/backup.py` | резервная копия базы |
| `scripts/test_book.py` | проверка всех сценариев |

## Запуск

```bash
cd ~/workspace/recipe-bot
./run.sh          # туннель + API + бот; Ctrl+C — остановить всё
```

Проверить, что живо:

```bash
curl -s localhost:8891/api/meta | head -c 200      # API отвечает
.venv/bin/python scripts/test_book.py              # 21 проверка
```

После перезагрузки мака: снова `./run.sh`. Данные не теряются — они в `data/recipes.db`.

## Резервная копия и восстановление

```bash
.venv/bin/python scripts/backup.py     # backups/recipes-ГГГГММДД-ЧЧММ.db, хранится 14 копий
```

Восстановление:
1. остановить `run.sh`;
2. скопировать нужный файл в `data/recipes.db` (старый убрать);
3. запустить `./run.sh`.

Снимок сайта пересобирается из базы автоматически при любом изменении.

## Деньги

- Расшифровка речи — локально, бесплатно (~30 сек на 5 минут видео).
- Хранение — SQLite + GitHub Pages, бесплатно.
- Хостинг API — свой мак, бесплатно.
- LLM нужен только чтобы превратить текст/расшифровку в структуру рецепта. Работает на
  подписке OpenCode Go (уже оплачена, ~копейки за рецепт). Без него продолжают работать:
  библиотека, поиск, фильтры, избранное, план, покупки, настройки, правка вручную.

## Ограничения (честно)

- **Мак должен быть включён** для импорта новых ссылок и любых правок. Читать книгу можно всегда.
- **Instagram** отдаёт видео только залогиненным и часто блокирует по IP. Бот пробует cookies
  из Chrome; если не вышло — просит залогиниться или говорит, что пост недоступен.
- **Текст на экране видео** (без речи и без описания) не читается — только звук и подписи.
- **Адрес туннеля меняется** при перезапуске: `run.sh` сам обновляет `api.json`; открытый экран
  может требовать перезагрузки.
- **Фото блюда** берётся из источника; у Instagram/TikTok ссылки на превью со временем истекают.
- Если в источнике нет данных (время, порции, граммовки) — так и показывается, ничего не выдумывается.

## Доступ

Бот и правки закрываются белым списком: `~/.hermes/cache/recipe-bot/allowed.json`
(`private: true` + id). Команды в чате: `/access`, `/allow <id>`, `/deny <id>`, `/public`, `/private`, `/id`.

**Сейчас бот закрыт**: `private: true`, доступ только у `184333195` (ваш id). Чужой человек
получит «🔒 Бот приватный» и свой id, который вы можете добавить командой `/allow <id>`.
Открыть всем — `/public`, закрыть снова — `/private`. Права на команды только у владельца.

## Обновление кода

Проект — локальный git-репозиторий, сайт публикуется из него же:

```bash
git log --oneline -3
./run.sh                     # после правок кода
.venv/bin/python scripts/publish.py -m "новый вид"   # пересобрать сайт
```
